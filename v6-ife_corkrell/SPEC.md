# 科可瑞尔 IFE 单事件产品规格

## 1. 文档信息

| 项 | 内容 |
| --- | --- |
| 文档状态 | 待评审的实施基线 |
| 数据源 | 科可瑞尔 IFE，UDP `8096`，`ife_cockrell.behavior` |
| 页面 | 乘客实时动态、数据管理 |
| 前端 | Vue 3 + TypeScript + Vite |
| 后端 | Java 21 + Spring Boot + MyBatis + Flyway |
| 数据库 | PostgreSQL |

本规格只授权科可瑞尔 IFE 单事件改造。飞机轨迹、用户管理、舷窗、地面流量、633 IFE 和其他接口继续遵循各自既有契约。

## 2. 目标

客户的科可瑞尔 IFE 每次发生乘客行为时，只下传该乘客的一条固定 JSON 事件。平台应接收这类事件、保留其历史记录，并以航班和座位为单位维护最新状态，使乘客实时页面始终能展示完整 282 座位客舱，而不把未收到事件错误显示为空闲。

成功标准：

1. 单用户客户报文无需批量包装即可被 UDP `8096` 接收。
2. 每条事件可在数据管理页面追溯原始报文和解析结果。
3. 同一航班同一座位只以最新事件驱动实时页面。
4. 282 名乘客短时间同时触发时，不同座位的事件不丢失、不互相覆盖。
5. 新航班的事件不会与旧航班状态混合。

## 3. 范围

### 3.1 本期实现

- 科可瑞尔固定单事件 JSON 的 UDP 解析和字段映射。
- 原始 UDP 报文和解析后的事件历史入库。
- `ife_cockrell_current_state` 当前状态表及条件 UPSERT。
- 乘客实时快照按当前航班返回 282 个固定座位。
- 默认空闲展示、乱序保护、同座位最新事件覆盖。
- 模拟器的单事件、普通突发、全舱突发场景。
- 后端、前端和模拟器的自动化验证。

### 3.2 本期不实现

- 修改客户科可瑞尔 JSON 字段、层级、端口或传输方式。
- 修改 633 IFE 的协议或发送逻辑。
- WebSocket、SSE、Redis、消息队列、对象存储或新数据库服务。
- IFE 内容封面下载、文件分片协议或封面资源管理。
- 更改数据管理、用户管理、轨迹或舷窗的产品范围。

## 4. 单事件业务规则

### 4.1 事件归属

每条科可瑞尔事件由 `sysInfo.flightId` 明确归属航班，由 `paxInfo.seatNo` 定位座位。当前状态逻辑键为：

```text
flightId + seatNo
```

`paxInfo.userId` 用于乘客识别与展示，不能替代座位键。一个航班内收到同一座位的新事件时，只更新该座位；其他座位维持已有状态。

### 4.2 时间与乱序

- `sysInfo.timestamp` 是业务事件时间，格式为 `yyyy-MM-dd HH:mm:ss.SSS`，按应用配置时区 `Asia/Shanghai` 解析。
- 同一 `flightId + seatNo` 中，事件时间较新的记录覆盖较旧记录。
- 事件时间相同，以后到达的 `received_at` 作为稳定并列规则。
- UDP 重发造成的重复历史记录不影响当前状态；当前状态仍是同座位的最后有效事件。

### 4.3 初始、新航班和缺失状态

- 页面按照 C929-700 固定座位清单生成 282 个座位。
- 当前航班中未收到事件的座位不含行为事件字段；前端展示为“空闲”。
- 接收新的 `flightId` 后，实时页面选择该航班的当前状态；旧航班记录不混入新航班。
- 未收到事件的座位不含影音、浏览、购物和带宽数据，不得进入影音排行。

## 5. 突发事件

事件触发不表示事件稀少。起飞后娱乐开放、IFE 重连、网络恢复或集中操作时，可能在极短时间连续到达 282 条单用户事件。

- 每一条 UDP 数据报独立解析、历史入库和更新当前状态。
- 不同座位使用不同的数据库主键行，允许并发 UPSERT。
- 处理中间状态允许前端暂时看到部分座位已更新；下一轮轮询读取已完成的最新快照。
- UDP 本身不保证送达。若业务要求最终完整性，客户侧应在连接建立/重连时发送当前状态初始化事件，或提供周期性全量同步、序号及重发能力；本阶段不擅自改变固定协议。

## 6. 数据管理和实时展示

- 数据管理页读取 `data_record` 和 `ife_cockrell_behavior`，一条事件对应一条数据记录和一条行为记录。
- 乘客实时页读取 `ife_cockrell_current_state`，不在每次查询时扫描和归并全部历史事件。
- 原始报文、PNR、IP、购物订单和封面字段只按现有数据权限在数据管理详情中可见；乘客实时接口不得默认暴露无展示必要的敏感字段。
- `trafficBytes` 是浏览累计字节数，不能作为实时带宽。带宽继续来自既有流量记录口径。

## 7. 模拟器规则

- `ife_cockrell.behavior` 端口保持 `8096`。
- 每个发送数据报是客户固定的根对象：`sysInfo`、`paxInfo`、`behaviorInfo`、`extInfo`。
- 模拟器不得为科可瑞尔事件添加批量包装字段。
- 支持单座位事件、普通混合突发和 282 座位全舱突发；全舱突发应发送 282 个独立数据报。
- 保留固定随机种子，使场景和测试可复现。

## 8. 验收标准

1. 客户样例格式可以被 UDP `8096` 解析并入库。
2. 客户字段 `extInfo.errorDesc` 正确映射到后端错误描述。
3. 每条事件在数据管理页可按航班、座位、乘客和时间追溯。
4. 单座位事件只改变当前状态表中对应的 `flightId + seatNo` 行。
5. 同一座位的旧事件不能覆盖新事件；时间相同按接收时间稳定处理。
6. 282 条独立事件突发后，当前航班快照可返回 282 个已更新座位。
7. 未收到事件的座位稳定显示“空闲”，且不显示虚构业务内容。
8. 新航班状态与旧航班不混合。
9. 633 IFE、QAR、舷窗、流量、登录和用户管理回归不受影响。
10. 后端测试、前端类型检查/测试/构建和模拟器测试通过。
