# 科可瑞尔 IFE 单事件阶段契约

本目录定义科可瑞尔 IFE（`ife_cockrell.behavior`，UDP `8096`）从“模拟器全员分页批量上报”调整为“固定格式的单乘客事件上报”后的产品、接口、数据库和实施边界。

## 必读顺序

1. `SPEC.md`：范围、事件语义、实时页面规则和验收标准。
2. `API.md`：UDP 单事件契约及现有乘客实时快照 API 的消费规则。
3. `schema.md`：历史事件表复用、当前状态表和 UPSERT 规则。
4. `SLICES.md`：实施顺序、文件范围和验证标准。
5. `AGENTS.md`：开发约束和禁止事项。

同时必须阅读：

- `../v1-docs` 基础契约和当前 UDP、数据管理源码；
- `../v2-phase2-contracts` 乘客实时页面契约；
- `../simulator/接口格式Schema.md`、`../simulator/数据模拟器开发指导.md`；
- 客户提供的 `KKRE接口测试_输出JSON格式.docx`。

## 授权边界

本阶段只调整科可瑞尔 IFE 的 UDP 接收、模拟发送、事件历史入库和当前座位状态读取：

- UDP `8096` 接收客户固定的单用户事件对象。
- 每条事件保留为历史数据，供数据管理页面和审计使用。
- 为每个 `flightId + seatNo` 保存最新状态，供乘客实时页面返回完整客舱快照。
- 模拟器支持单事件、普通突发和全舱突发测试。

`ife_633.behavior`（UDP `8095`）不在本阶段范围内；除非取得其独立的客户协议，否则不得按科可瑞尔格式修改。

## 核心决策

- 客户的 JSON 格式是固定协议；后端和模拟器必须适配，不能要求客户增加 `items`、`page`、`messageType` 或 `sentAt` 包装。
- `ife_cockrell_behavior` 继续保存全部事件历史，不改成“每座位仅一行”。
- 新增 `ife_cockrell_current_state` 保存同航班同座位的最新状态；它不是历史事实表。
- 当前页面默认显示 282 个 C929-700 固定座位。没有收到对应航班事件时，事件字段为空，前端展示为“空闲”。
- 单事件可以在短时间内形成 282 条 UDP 数据报的全舱突发；协议仍保持“一名乘客一条数据报”。
