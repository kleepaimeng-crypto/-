# 原始 JSON 报文导出产品规格

## 1. 文档信息

| 项 | 内容 |
| --- | --- |
| 功能 | 数据管理原始报文导出 |
| 数据源 | `data_record.raw_payload` |
| 输出格式 | CSV、PDF |
| 前端 | 现有数据管理导出区域 |
| 后端 | Java 21 + Spring Boot |
| 数据库 | 不新增表和 Flyway 迁移 |

## 2. 目标与范围

用户在数据管理页面选择一个数据类型并设置已有筛选条件后，可以创建 CSV 或 PDF 导出任务。任务读取所有匹配的有效 JSON 数据记录，生成仅包含原始 JSON 内容的文件，并在完成后提供下载。

本阶段实现：

- 复用数据管理页已有的数据类型、筛选、排序、导出格式和导出历史界面。
- 以后台任务生成 CSV、PDF，避免大结果集占用单个 HTTP 请求。
- CSV 的每一行写入一条完整 JSON 报文；PDF 按报文逐条排版。
- 查询任务状态、历史记录和下载已完成文件。
- 对空结果、无可导出 JSON、生成失败和文件不存在给出明确状态。

本阶段不实现：

- 导出解析后的 QAR、IFE、舷窗、流量等业务明细字段。
- 导出 `raw_text`、二进制 UDP 原包或逐字节还原上游字符串。
- Excel、JSON、ZIP、图片、报表统计、定时导出、邮件发送或对象存储。
- 新建导出页面、修改既有数据管理筛选含义或修改原始报文内容。

## 3. 业务规则

- 导出范围与创建任务时的数据管理筛选条件完全一致；任务创建后使用保存的筛选快照，不受后续页面筛选变化影响。
- 每个任务必须指定一个数据类型，排序规则沿用数据管理页的 `dataType`、`sentAt` 或 `receivedAt` 及升降序。
- 只导出 `raw_payload` 非空的记录。`raw_payload` 为空而仅有 `raw_text` 的记录跳过，并在任务结果中计入失败/跳过数量。
- JSON 内容从 `jsonb` 读取并重新序列化；字段和值不变，但格式、空白和字段顺序可能不同。
- CSV 使用 UTF-8 with BOM，并正确转义 JSON 中的双引号、逗号和换行；输出列固定为 `raw_json`。
- PDF 使用等宽字体和自动换行，每条报文单独分段；JSON 较长时允许自然分页，不得截断或省略字段。
- 导出文件只在任务成功后可下载。任务失败、未完成、无权限或文件缺失时不得返回部分文件。
- 历史记录仅对创建该任务的已登录用户可见和下载，除非现有数据管理权限模型另有更高权限规则。

## 4. 安全与性能

- 导出接口继承现有 Spring Security，不增加匿名访问。
- 不在响应中直接拼接全部 JSON；生成过程采用分页读取和流式写文件，避免一次性加载全部结果。
- 下载接口只允许读取任务实际生成的受控文件路径，禁止由请求参数指定服务器路径。
- 原始报文可能含 PNR、终端 IP、订单或封面 Base64；文件下载权限与数据管理权限保持一致，不新增公开链接。
- 文件名不包含 PNR、航班号、IP、用户名或原始报文内容。

## 5. 验收标准

1. 按数据类型、航班号、时间范围等筛选创建 CSV、PDF 任务，结果集与数据管理查询一致。
2. CSV 中每一行可解析为一条 JSON，字段和值与对应 `raw_payload` 一致。
3. PDF 中每条 JSON 完整输出，长 JSON 不截断。
4. 含中文、引号、逗号、换行及 Base64 的 JSON 不破坏 CSV 结构。
5. 仅有 `raw_text` 的记录不被误当作 JSON 导出，任务结果明确记录跳过数量。
6. 未登录用户、非创建人、未完成任务和文件缺失场景不能下载文件。
7. 不产生数据库迁移，不修改既有 UDP、QAR、IFE、舷窗和乘客实时逻辑。
