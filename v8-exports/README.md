# 原始 JSON 报文导出阶段契约

本目录定义数据管理页面按筛选条件导出原始 JSON 报文的产品、接口、数据和实施边界。

## 必读顺序

1. `SPEC.md`：功能范围、导出规则和验收标准。
2. `API.md`：导出任务、历史和下载接口契约。
3. `schema.md`：既有数据表和原始 JSON 的边界。
4. `SLICES.md`：实施顺序和验证命令。
5. `AGENTS.md`：开发约束。

## 核心决策

- 导出对象是数据管理页筛选出的 `data_record`，不是 QAR、IFE 等解析后的业务明细表。
- 每条有效 JSON 报文从 `data_record.raw_payload` 读取，导出其字段和值。
- CSV 和 PDF 均只包含原始 JSON 报文内容；不附加解析字段、图表、统计或业务摘要。
- `raw_payload` 是 PostgreSQL `jsonb`，导出的 JSON 不保证保留上游报文的空格、换行和字段顺序，但字段和值保持一致。
- 非 JSON 原始文本 `raw_text` 不属于本期导出范围。
- 复用现有“创建导出任务、导出历史、下载文件”页面入口和 `file_job` 任务模型。

## 用户可见结果

- CSV：第一列为 `raw_json`，一条数据记录一行；JSON 作为完整的 CSV 字段写入。
- PDF：按导出顺序逐条输出格式化 JSON，并明确区分相邻报文。
- 导出成功后可从导出历史下载对应文件。

带 `coverBase64` 的 IFE 原始报文可能很大。导出文件保留完整 JSON；但 Excel 单元格有长度限制，超长报文不保证能在 Excel 中完整显示，建议使用文本编辑器或 JSON 工具查看 CSV 文件。
