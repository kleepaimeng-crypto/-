# 原始 JSON 报文导出实施规则

## 1. 必读顺序

1. `SPEC.md`
2. `API.md`
3. `schema.md`
4. `SLICES.md`
5. 本文件
6. 当前数据管理、`data_record`、`file_job`、Spring Security 和前端文件下载源码

如有冲突，优先级为 `SPEC.md`、`API.md`、`schema.md`、`SLICES.md`、本文件。

## 2. 范围

只实现：

- 已勾选数据记录的原始 JSON 导出，且按数据类型拆分 CSV。
- CSV 后台导出任务、历史查询和受控下载。
- 现有数据管理导出入口的前后端联通。

禁止顺手实现：

- 导出解析后的业务明细、PDF、Excel、JSON、ZIP、报表、图表、邮件、对象存储或定时任务。
- 修改 UDP 接收、QAR、IFE、舷窗、轨迹、乘客实时、用户管理或数据管理筛选语义。
- 新增数据库迁移、修改已发布迁移或删除历史数据。
- 将任意服务器路径、文件 URL 或原始报文公开给未授权用户。

## 3. 数据规则

- 唯一导出来源是 `data_record.raw_payload`；不得从解析后的业务表重建 JSON。
- 允许 `jsonb` 重新序列化，不承诺保留空格、换行或字段顺序。
- `raw_text` 不是 JSON 导出对象，不能伪装成 JSON 写入文件。
- 不得截断 JSON、Base64、中文或特殊字符；CSV 必须标准转义。
- 每个任务必须保存创建时的记录 ID 快照和数据类型；生成文件时不得读取前端后续变化的筛选条件。

## 4. 安全与性能规则

- 所有导出、历史和下载接口必须要求现有登录权限。
- 仅任务创建人可查看和下载自己的任务，除非已有权限模型明确授予更高权限。
- 导出生成采用分页查询和流式写入，不得全量加载到 JVM 内存。
- 下载只能根据受控任务 ID 解析服务端文件；禁止接收路径参数和目录遍历。
- 错误响应不得包含服务器绝对路径、SQL、原始报文或堆栈。

## 5. 验证

- 后端覆盖：筛选快照、CSV 转义、长报文、空结果、`raw_text` 跳过、权限和下载状态。
- 前端覆盖：创建任务、状态展示、历史刷新、成功下载与失败提示。
- 至少执行 `backend` 的 `test`、`verify` 和 `frontend` 的 `typecheck`、`test`、`build`。
