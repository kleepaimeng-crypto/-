# 原始 JSON 报文导出阶段契约

本目录定义数据管理页面按已勾选记录导出原始 JSON 报文的产品、接口、数据和实施边界。

## 必读顺序

1. `SPEC.md`：功能范围、导出规则和验收标准。
2. `API.md`：导出任务、历史和下载接口契约。
3. `schema.md`：既有数据表和原始 JSON 的边界。
4. `SLICES.md`：实施顺序和验证命令。
5. `AGENTS.md`：开发约束。

## 核心决策

- 数据类型可多选，用于筛选左侧数据列表；左侧记录支持跨页多选。
- 导出对象是左侧勾选的 `data_record`，不是当前筛选结果中的全部记录，也不是 QAR、IFE 等解析后的业务明细表。
- 后端按勾选记录的数据类型拆分，每种类型创建一个 CSV 和一条导出历史。
- 每条有效 JSON 报文从 `data_record.raw_payload` 读取，导出其字段和值。
- CSV 将原始 JSON 的键展开为列；不附加图表、统计或业务摘要。
- `raw_payload` 是 PostgreSQL `jsonb`，导出的 JSON 不保证保留上游报文的空格、换行和字段顺序，但字段和值保持一致。
- 非 JSON 原始文本 `raw_text` 不属于本期导出范围。
- 复用现有“创建导出任务、导出历史、下载文件”页面入口和 `file_job` 任务模型。

## 用户可见结果

- CSV：第一行为字段名，后续每行是一个数据项的字段值。嵌套对象使用点号列名，例如 `sysInfo.timestamp`；顶层 `items` 数组中的每个元素展开为一行，并保留外层公共字段。
- 导出成功后可从导出历史下载对应文件。
- 下载文件名为“数据类型 + 日期”，例如 `QAR-20260825.csv`；服务器内部使用任务 ID 保存文件以避免重名。
- 导出历史在存在等待中或处理中的任务时每 2 秒自动刷新，全部结束后停止刷新。
- 已结束的导出历史可删除，删除时同时删除对应 CSV 文件。

带 `coverBase64` 的 IFE 原始报文可能很大。导出会将其作为独立列保留；但 Excel 单元格有长度限制，超长 Base64 不保证能完整显示，建议使用文本编辑器查看。
